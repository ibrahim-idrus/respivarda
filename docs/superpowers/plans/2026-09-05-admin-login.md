# SmokeWatch Admin Login Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a responsive, UI-only `/admin/login` page that gives administrators a clear entry point while preserving the public dashboard as the guest experience.

**Architecture:** Keep `app/admin/login/page.tsx` as a small App Router server entry with route metadata. Put interactive form state and local validation in a focused client component under `src/components/admin/`, and keep the operations preview presentational so it cannot imply real data access. Add only a discreet public-header link; do not add sessions, proxy protection, credential APIs, or Telegram integration.

**Tech Stack:** Next.js 16.3.4 App Router, React 19, TypeScript, Tailwind CSS v4 tokens already defined in `app/globals.css`, `@cloudflare/kumo` buttons, `@phosphor-icons/react`, Node’s built-in test runner, and `tsx` for loading TypeScript tests.

**Spec:** `docs/superpowers/specs/2026-09-05-admin-login-design.md`

## Global Constraints

- Route: `/admin/login`.
- The current public dashboard remains the guest experience at `/`.
- This pass is UI-only: no credential validation against a provider, session, `next-auth`, cookies, proxy, database, Telegram OAuth, or admin dashboard data.
- The exact heading is `Sign in to Operations`.
- The primary action is labeled `Sign in to admin console`.
- A valid local submission must say `Preview only — authentication is not connected yet`; it must not claim the user is signed in.
- The layout is two-panel on desktop and stacks with the sign-in card first on small screens.
- Reuse Plus Jakarta Sans, the existing SmokeWatch color tokens, rounded cards, teal accents, navy surfaces, and Phosphor icons.
- Every form control has a visible label, stable `id`/`htmlFor`, native input semantics, visible keyboard focus, and error/status associations.
- Keep preview numbers visibly labeled as preview data; do not present them as a live API response.
- Do not introduce a role selector; the route itself identifies the administrator audience.
- Limit motion to short color/opacity transitions; no essential information may depend on animation.

- [ ] **Step 4: Implement the minimal validation helper**

Create `src/components/admin/admin-login-validation.ts`:

```ts
export type AdminLoginValues = {
  email: string;
  password: string;
};

export type AdminLoginErrors = {
  email?: string;
  password?: string;
};

export function validateAdminLogin({
  email,
  password,
}: AdminLoginValues): AdminLoginErrors {
  const errors: AdminLoginErrors = {};
  const normalizedEmail = email.trim();

  if (!normalizedEmail) {
    errors.email = "Enter your work email.";
  } else if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(normalizedEmail)) {
    errors.email = "Use a valid work email.";
  }

  if (!password.trim()) {
    errors.password = "Enter your password.";
  }

  return errors;
}
```
